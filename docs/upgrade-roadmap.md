# 应用与发布升级路线

目标是继续完善现有网页，并让网页、Skill 和 MCP 复用同一套绘图能力。CLI 作为可选扩展；根目录 Next.js 应用及现有 Vercel 部署方式保留。

## 第一阶段：生成与编辑可靠性（已完成）

- 单个生成任务贯穿流读取、续写和重试；停止生成会取消待执行任务与上游请求。
- 生成、画布、工具和撤销重做通过同一文档提交入口更新。初始化空画布及内容相同的回传不影响任务或历史栈。
- XML 在浏览器和 Node.js 中执行语法与图结构校验；无效或截断输出保留为代码草稿，原图继续可用。
- 自动保存已应用图、未应用代码和未发送输入，刷新后分别恢复；工作区快照排除模型配置、密钥和图片数据。
- 请求大小、图片大小、总超时和空闲超时设限；流错误向用户返回经过处理的信息。
- Next.js 与对应 ESLint 配置升级至 16.3.8。修正文档中的未实现服务端配置及导出功能标记。

验证：240 个单元测试、8 个浏览器测试、ESLint、生产构建通过。浏览器测试覆盖真实 Next API 到模拟模型服务的请求链路，以及归一化回传后的撤销重做和无效 JSON 应用保护。Draw.io iframe 消息协议由测试替身模拟；真实远端编辑器冒烟在等待窗口内未收到初始化消息，未验证其实际渲染。

JSON 兼容输入拒绝未知类型或不合法元素，失败时保留原图和草稿。显式应用空数组 `[]` 表示创建空图，仍可撤销恢复。

本阶段支持未压缩 Draw.io XML。压缩页面、PNG/SVG 导出、完整服务端凭据托管，以及全量依赖审计问题仍需后续工作。网页生产部署单独推进，线上地址保持现有版本。

## 第二阶段：共享核心（已完成）

`packages/core/src` 提供校验、显式修复、主题/样式/布局处理、图类型提示和模型适配。原有 `lib` 路径桥接同一实现，网页继续使用现有 API 与流式交互。

核心在真实 Node.js 环境运行，不依赖 Next.js 路径别名、React、浏览器全局 DOM 或 localStorage。XML 运行时选择浏览器 DOM 或 xmldom，不污染全局。多页布局、重叠和间距处理按页面隔离相同节点 ID，样式变换保留命名形状。

## 第三阶段：本地 MCP（实现与安装验证完成）

`packages/mcp` 提供五个工具：`generate_drawio`、`validate_drawio`、`repair_drawio`、`style_drawio`、`list_drawio_options`。输入和结构化输出都有 schema；取消贯穿模型请求，失败结果不返回可误应用的 XML。

模型配置从 MCP 进程环境读取；校验、修复、样式和选项查询不需要密钥。服务返回 XML，由客户端负责保存文件。独立 npm 包包含共享核心，已在仓库外的临时安装环境中完成 stdio 握手、工具发现和调用验证。

已通过 SDK stdio 客户端真实调用生成与校验工具，经 OpenAI 兼容网关请求 `codex/gpt-6.1-sol` 生成 Transformer 图并用官方 Draw.io 查看器渲染。没有远程 HTTP MCP 地址；远程模式作为后续扩展，需要明确认证、模型费用及持久化存储边界。

## 第四阶段：Skill（实现与独立使用验证完成）

`skills/smart-drawio` 封装科研结构、架构和流程绘图，包含指令、按需参考、两个可编辑模板和 Python 标准库校验脚本。助手可用自身模型创建 XML，MCP 为可选增强，不需要完整 CLI 或另配生成模型。

官方 Skill 元数据检查与 11 项独立脚本测试通过。独立代理在复制后的 Skill 目录中完成了论文方法结构图，没有使用网站、仓库源码或外部模型凭据。另一次实际 Skill 调用生成了 Transformer 图，完成离线校验、官方 Draw.io 渲染和独立技术审核。

整体验证：291 个 JavaScript 单元及协议测试、11 个 Python Skill 测试、8 个生产构建浏览器用例、ESLint 与 Next.js 生产构建通过。实际 MCP tarball 与 Skill ZIP 都在仓库外独立安装验证。浏览器回归中的 Draw.io 消息协议使用替身；MCP 工作流示例另外通过官方 Draw.io 静态查看器实际渲染，修复了无效箭头类型与连线标签错误换行。远端嵌入编辑器的完整编辑交互仍需后续验证。

## 第五阶段：公开发布与生产部署（分别推进）

已补独立包元数据、Registry `server.json`、安装说明、许可证声明、来源说明、打包和安装验证脚本，以及 CI 验证流程。CI 文件已配置，本轮检查在本地运行，尚未执行 GitHub 托管 CI。

Skill/MCP 的版本入口为 `tools-v0.1.0`，使用独立发布分支与标签，网页生产部署保持现状。已核对 npm 账号和上游 MIT README 声明，并保留上游来源；Registry 需在 npm 版本公开可取后登记。具体发布流程见 [打包与发布](publishing.md)，Skill 使用见 [安装说明](skill-installation.md)。

Vercel Preview 的实际远端编辑器验证通过后，再推广生产版本。压缩页面、PNG/SVG 导出、远程 MCP、服务端托管模型和完整 CLI 均作为后续可选工作。
