# 交付质量

先检查图能否独立解释用户要表达的关系，再检查 XML 和外观。

| 场景 | 重点 |
|---|---|
| 科研方法或模型图 | 输入、核心模块、输出、训练关系各自清楚；符号与原文一致；没有编造模块、指标或实验结果 |
| 系统架构图 | 服务、存储、外部系统及职责边界明确；每条重要箭头有方向，必要时说明协议或数据 |
| 流程图 | 起点和终点可辨认；判断分支有条件；循环能说明返回位置；没有无意的断路 |
| 修改已有图 | 用户要求外的布局和语义保留；稳定 ID、容器本地坐标、页面名称未被意外改变 |

视觉检查参考：

- 同类节点保持尺寸与样式一致；留足节点、容器标题和图例的间距。边标签不能覆盖节点文字。
- 科研图优先克制的浅色填充、深色文字及少量语义强调色；用线型、分组或标记辅助区分，避免仅靠红绿表达状态。
- 选择 Arial、Helvetica 等目标环境常见字体；中文采用目标环境可用的中文字体。字号结合最终展示尺寸检查，模板字号不构成期刊规范保证。
- 连线遵循主阅读方向；分支、回路和跨容器边保留其实际含义。不要为了整齐删除关系。
- 如果能渲染，打开实际图并检查文字截断、重叠、边穿过节点、图例及页面边界。没有渲染条件时，明确只完成结构校验。

最终至少交付 `.drawio` 文件及简短变更说明。若用户另需图片或 PDF，使用实际导出工具生成并检查结果；不要把 XML 改后缀冒充其他格式。说明修复导致的内容丢弃、缺少参考材料或尚未视觉验证的部分。
